# 멀티 에이전트 감독자

감독자가 사용자 요청을 해석해 적절한 전문 에이전트에게 작업을 맡기고 각 결과를 모아 최종 응답을 구성하는 구조

## 패턴

- 도구 호출
  - 감독자가 다른 에이전트를 도구처럼 호출
  - 전문 에이전트는 사용자와 직접 대화하지 안고 결과만 반환.
  - 흐름을 강하게 통제해야 할 때 적합
- 핸드오프
  - 현재 에이전트가 다른 에이전트에게 대화의 제어권 자체를 넘김
  - 사용자가 이후 해당 전문가와 직접 상호작용
  - 도메인을 오가는 상담에 적합

## 커스텀 감독자 직접 구현하기

- Command 객체로 핸드오프를 직접 구현할 수 있음
- InjectedState, InjectedToolCallId로 런타임 상태를 주입 받아 대상 에이전트로 제어권을 넘기는 Command 객체를 반환 
- e.g. Command(goto=agent_name, graph=Command.PARENT)

## 명시적 작업 설명 핸드오프 도구

- Command 객체에 Send 패턴을 사용하여 감독자가 구체적인 작업 설명을 작성해 에이전트에게 전달하여 정확성과 일관성이 높일 수 있음

## 계층적 에이전트

- 에이전트가 다음 단계의 에이전트를 도구로 호출하는 구조를 연결하여 계층적 에이전트 구현

## 도구 호출 방식과 핸드오프 방식 구분

"tools 파라미터에 넣었다"는 게 패턴을 가르는 기준이 아니라, 그 tool 함수 안에서 그래프를 뛰쳐나가는 특수 객체(Command)를 리턴하느냐, 그냥 값을 리턴하고 같은 노드 안에 머무르느냐가 진짜 구분점입니다. 스크래치 구현이 도구 호출처럼 "보인" 건 정확한 관찰이었고, 실제로 그 둘은 LLM 인터페이스 레벨에서는 동일하고 실행 엔진 레벨에서만 갈라지는 거예요.

```python
# 도구 호출 패턴 — 그냥 값을 반환
def call_basic_math(query: str) -> str:
    result = basic_math.invoke({"messages": [...]})
    return result["messages"][-1].content   # 문자열 반환

# 핸드오프 패턴 — Command 객체를 반환
def handoff_tool(state, tool_call_id) -> Command:
    return Command(
        goto=agent_name,          # 그래프의 "활성 노드"를 갈아치움
        update={...},
        graph=Command.PARENT,
    )
```
