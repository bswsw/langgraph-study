# 계층적 에이전트 팀

- 상위 감독자 → 팀 감독자 → 작업자로 이어지는 다단계 감독 구조
- 감독자 한 명이 모든 작업자를 지휘하면 관리 부담이 커지고 LLM 컨텍스트 윈도우 한계에 부딪힘
- 웹 연구(Research Team)와 문서 작성(Doc Writing Team)처럼 성격이 다른 작업을 전문 팀으로 분리
- AutoGen 논문(arXiv 2308.08155)의 아이디어를 LangGraph로 구현

## 팀 구성

- Research Team
  - Searcher: Tavily 웹 검색
  - WebScraper: URL 스크래핑
- Doc Writing Team
  - DocWriter: 문서 작성·편집
  - NoteTaker: 아웃라인 작성
  - ChartGenerator: 차트 생성 (Python REPL)

## 유틸리티

- create_team_supervisor: 모든 층의 감독자를 하나의 함수로 생성
  - with_structured_output + Literal[멤버 목록 + "FINISH"]로 라우팅 선택지를 강제해 잘못된 라우팅 방지
  - 라우팅 지시는 마지막 human 메시지로 전달 (Claude는 system 메시지가 맨 앞에 연속으로 있어야 하므로)
- AgentFactory: 에이전트 결과를 name이 붙은 HumanMessage로 변환
  - 감독자가 모든 결과를 같은 형식으로 받고, 어느 에이전트의 결과인지 구분 가능
  - 에이전트 내부의 도구 호출 과정은 버리고 마지막 메시지만 감독자에게 전달
- preprocess | agent: 에이전트 실행 직전에 작업 디렉터리의 파일 목록을 상태에 주입
  - 파일 시스템을 공유 작업 공간으로 사용 (e.g. DocWriter가 NoteTaker의 아웃라인 파일을 참조)

## 참고: create_agent_node와 클로저

- add_node에는 "state를 받아 업데이트를 반환하는 함수"를 넘겨야 함
- create_agent_node는 에이전트를 바로 실행하지 않고, 나중에 state를 받으면 실행할 함수(agent_node)를 만들어 반환
- LangGraph는 노드에 state만 넘기므로, agent와 name은 바깥 함수가 받아 두고 안쪽 함수가 기억함 → 클로저
- 파이썬은 언어 차원의 자동 커링이 없고, 클로저로 커링을 구현
  - 커링: f(a, b, c) → f(a)(b)(c)처럼 인자를 하나씩 받는 함수의 연쇄
  - 부분 적용: 인자 일부를 미리 고정해 나머지만 받는 함수를 만듦
  - create_agent_node(agent, name)(state)는 엄밀히는 부분 적용에 가까움
- 클로저 대신 functools.partial로도 같은 노드를 만들 수 있음

```python
# 클로저
def create_agent_node(self, agent, name: str):
    def agent_node(state):
        result = agent.invoke(state)
        return {"messages": [HumanMessage(content=result["messages"][-1].content, name=name)]}
    return agent_node

# functools.partial
def agent_node(state, agent, name):
    result = agent.invoke(state)
    return {"messages": [HumanMessage(content=result["messages"][-1].content, name=name)]}

search_node = functools.partial(agent_node, agent=search_agent, name="Searcher")
```

## 팀 그래프 패턴

- Research Team, Doc Writing Team 모두 같은 구조
- 작업자 → Supervisor 에지: 작업자는 작업 후 항상 감독자에게 보고
- Supervisor → 조건부 에지: get_next_node가 상태의 next 값을 반환해 다음 작업자 선택, "FINISH"면 END
- 시작 노드(entry point)는 Supervisor

```python
def get_next_node(x):
    return x["next"]

graph.add_edge("Searcher", "Supervisor")
graph.add_edge("WebScraper", "Supervisor")
graph.add_conditional_edges(
    "Supervisor", get_next_node,
    {"Searcher": "Searcher", "WebScraper": "WebScraper", "FINISH": END},
)
graph.set_entry_point("Supervisor")
```

## 슈퍼그래프

- 두 팀을 총 감독자 아래에 연결 (상향식 계획 정책)
- 컴파일된 팀 그래프도 Runnable이므로 파이프로 감싸 상위 그래프의 노드 하나로 추가 가능
- get_last_message | team_app | join_graph 패턴으로 서로 다른 상태 스키마를 연결
  - get_last_message: 슈퍼그래프 → 팀, 전체 히스토리 중 마지막 메시지만 전달
  - join_graph: 팀 → 슈퍼그래프, 팀 실행 결과 중 마지막 메시지만 반영
- 마지막 메시지만 주고받아 팀 내부 대화가 상위로 새지 않음 → 컨텍스트를 간결하게 유지

## 무한 루프 방지

- 계층적 시스템은 팀 간 반복 호출로 무한 루프가 생길 위험이 있음
- 프롬프트 규칙
  - "Do NOT repeat completed tasks"
  - 작업 순서(WORKFLOW) 명시
  - "Assign each team at most once"
- recursion_limit을 최종 안전장치로 설정 (계층이 깊으므로 충분히 크게, 보통 기본값 50)
- 계층적 감독자 체인은 stream_mode="messages"와 호환되지 않으므로 실행 시 invoke_graph 사용

## 주의
