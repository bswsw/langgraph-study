INTRO

두 조율 방식 비교

단일 에이전트에 너무 많은 도구와 판단을 맡기면 컨텍스트가 비대해지고 의사결정이 흐려진다. 11장과 12장은 이 문제를 서로 다른 방식으로 해결한다. 감독자(Supervisor) 패턴은 중앙의 조율자가 작업을 분해해 적절한 전문 에이전트에게 위임하고 결과를 모아 최종 응답을 만드는 하향식 구조다. 반면 협업 네트워크(Collaboration Network)는 상하 관계 없이 에이전트들이 자신의 판단에 따라 다음 에이전트에게 대화를 넘기며 작업 경로가 고정돼 있지 않은 수평적 구조다. 전자는 통제와 예측 가능성이 필요한 작업에, 후자는 조사·작성·검토처럼 단계가 유동적으로 오가는 작업에 적합하다.

CHAPTER 11

멀티 에이전트 감독자

감독자가 사용자 요청을 해석해 적절한 전문 에이전트에게 작업을 맡기고, 각 결과를 모아 최종 응답을 구성하는 구조. 시장 조사 후 수치 계산, 보고서 작성처럼 여러 단계의 판단이 필요한 작업에 특히 유용하다.

멀티 에이전트의 두 가지 패턴

TOOL CALLING

감독자가 다른 에이전트를 도구처럼 호출. 전문 에이전트는 사용자와 직접 대화하지 않고 결과만 반환. 흐름을 강하게 통제해야 할 때 적합.

HANDOFF

현재 에이전트가 다른 에이전트에게 대화의 제어권 자체를 넘김. 사용자가 이후 해당 전문가와 직접 상호작용. 도메인을 오가는 상담에 적합.

전문 작업자 에이전트 생성

create_agent로 특정 분야에만 집중하는 작업자를 만든다. 이 장의 예제는 웹 검색을 담당하는 Research 에이전트와 사칙연산·거듭제곱·백분율 계산을 담당하는 Math 에이전트 둘을 구성한다. 각 에이전트는 시스템 프롬프트에 "자신의 역할만 수행하고 완료되면 감독자에게 보고하라"는 규칙을 명시해 역할 범위를 벗어나지 않도록 한다.

python역할이 분리된 작업자 에이전트
research_agent = create_agent(
    model="claude-sonnet-4-5",
    tools=[web_search],
    system_prompt="research 전용. 계산은 하지 말고 감독자에게 결과만 보고.",
    name="research_agent",
)

math_agent = create_agent(
    model="claude-sonnet-4-5",
    tools=[add, multiply, divide, power, percentage],
    system_prompt="계산 전용. 검색은 하지 말고 감독자에게 결과만 보고.",
    name="math_agent",
)

라이브러리 기반 감독자 — langgraph-supervisor

create_supervisor 함수 하나로 핸드오프 로직과 그래프 구성을 자동 처리한다. add_handoff_back_messages=True로 작업자가 감독자에게 복귀할 때 메시지를 자동 기록하고, output_mode로 출력 형태(전체 히스토리 등)를 지정한다.

pythoncreate_supervisor로 감독자 구성
from langgraph_supervisor import create_supervisor

supervisor = create_supervisor(
    model=init_chat_model("claude-sonnet-4-5"),
    agents=[research_agent, math_agent],
    system_prompt="research/math 두 전문가에게 순차적으로 작업을 위임하고 결과를 종합.",
    add_handoff_back_messages=True,
    output_mode="full_history",
).compile()

"2024년 미국·뉴욕주 GDP를 찾고 비중을 계산하라"처럼 검색과 계산이 모두 필요한 복합 질문을 주면, 감독자가 transfer_to_research_agent → transfer_to_math_agent 순서로 위임하는 과정을 그대로 관찰할 수 있다.

스크래치 구현 — 핸드오프 메커니즘 직접 만들기

라이브러리 없이 Command 객체로 핸드오프를 직접 구현하면 내부 동작을 더 깊이 이해할 수 있다. 핸드오프 도구는 InjectedState, InjectedToolCallId로 런타임 상태를 주입받아, 대상 에이전트로 제어권을 넘기는 Command(goto=agent_name, graph=Command.PARENT)를 반환한다.

python핸드오프 도구 팩토리
def create_handoff_tool(*, agent_name: str, description: str | None = None):
    name = f"transfer_to_{agent_name}"

    @tool(name, description=description)
    def handoff_tool(
        state: Annotated[MessagesState, InjectedState],
        tool_call_id: Annotated[str, InjectedToolCallId],
    ) -> Command:
        tool_message = {
            "role": "tool", "name": name, "tool_call_id": tool_call_id,
            "content": f"Successfully transferred to {agent_name}",
        }
        return Command(
            goto=agent_name,
            update={"messages": state["messages"] + [tool_message]},
            graph=Command.PARENT,   # 서브그래프가 아닌 부모 그래프 레벨에서 라우팅
        )
    return handoff_tool

이렇게 만든 핸드오프 도구를 감독자 에이전트의 tools로 전달하고, StateGraph에 작업자 노드를 추가한 뒤 각 작업자에서 다시 supervisor로 돌아오는 엣지를 연결하면 라이브러리와 동일한 구조가 완성된다.

고급 작업 위임 — 명시적 작업 설명

기본 구조는 전체 대화 히스토리를 그대로 전달하지만, 대화가 길어질수록 작업 의도가 흐려질 수 있다. Send 패턴을 사용하면 감독자가 구체적인 작업 지시문(task_description)을 직접 작성해 에이전트에게 전달할 수 있어, 정확성과 일관성이 높아진다.

전체 히스토리 전달명시적 작업 설명(Send)
입력대화 전체 메시지감독자가 작성한 구체적 지시문
장점구현이 단순정확성 ↑, 컨텍스트 해석 부담 ↓, 결과 일관성 ↑
단점대화가 길어지면 의도 희석감독자가 매번 지시문을 잘 작성해야 함

고급 패턴 — 계층적 에이전트

최상위 에이전트가 중간 레벨 에이전트를 도구로 호출하고, 중간 레벨이 다시 하위 에이전트를 호출하는 다단계 구조. 이 장의 예제는 3단계 수학 에이전트로 구성한다 — 계층3(기본 산술) → 계층2(중간 수준 조합) → 계층1(복잡한 문제 분해). 감독자 패턴과 달리 도구 호출(tool-calling) 방식만으로 계층을 표현하며, 각 레벨은 @tool로 래핑되어 상위 에이전트에서 함수처럼 호출된다.

실전 응용 — 고객 지원 시스템

기술 지원 · 청구 지원 · 일반 지원 세 전문 에이전트를 감독자가 문의 내용에 따라 라우팅하는 실무형 예제. 콜센터에서 상담원이 문의 유형을 파악해 적절한 부서로 연결하는 구조와 동일하다.

기술 지원

시스템 상태 확인, 서비스 재시작 등 오류·기술 질문 처리

청구 지원

인보이스 조회, 환불 처리 등 결제 관련 문의 처리

일반 지원

영업시간, 제품 정보 등 도구 없이 일반 문의 응대

감독자는 call_tech_support, call_billing_support, call_general_support 세 도구 중 문의 내용에 맞는 것을 선택해 호출하며, 환불 처리 전 인보이스를 먼저 확인하도록 지시하는 등 업무 순서 규칙도 시스템 프롬프트에 포함된다.

CHAPTER 12

멀티 에이전트 협업 네트워크

여러 에이전트가 고정된 상하 관계 없이 서로 작업을 넘기며 문제를 해결하는 구조. 감독자가 중앙에서 조율하는 대신, 각 에이전트가 자신의 판단에 따라 다음 에이전트나 도구로 흐름을 이어간다. 조사 → 작성 → 검토처럼 경로가 하나로 고정돼 있지 않은 문제에 적합하다.

Research · Chart Generator 에이전트

이 장의 예제는 웹 검색 도구(TavilySearch)를 쓰는 Research 에이전트와, 파이썬 코드를 실행해 matplotlib 차트를 그리는 Chart Generator 에이전트 두 협업자로 구성된다. 두 에이전트 모두 공통 시스템 프롬프트 생성 함수를 공유해 "협업 중임을 인지하고, 완료 시 응답 앞에 FINAL ANSWER를 붙인다"는 규칙을 갖는다.

python공용 시스템 프롬프트 · 노드 함수
def make_system_prompt(suffix: str) -> str:
    return (
        "You are collaborating with other assistants. "
        "If you have the final answer, prefix your response with FINAL ANSWER."
        f"\n{suffix}"
    )

def research_node(state: MessagesState) -> MessagesState:
    result = research_agent.invoke(state)
    last_message = HumanMessage(content=result["messages"][-1].content, name="researcher")
    return {"messages": [last_message]}

노드 함수가 에이전트 출력을 name 필드가 있는 HumanMessage로 감싸는 이유는, 다른 에이전트가 "이 메시지를 누가 보냈는지" 구분할 수 있게 하기 위함이다.

Chart Generator의 시스템 프롬프트에는 운영체제별 한글 폰트 설정(맥 AppleGothic, 윈도우 맑은 고딕, 리눅스 NanumGothic) 코드가 포함돼 있어, 생성되는 차트에서 한글이 깨지지 않도록 한다.

라우터와 종료 조건

라우터 함수는 마지막 메시지에 FINAL ANSWER가 포함됐는지 확인해 그래프를 종료할지, 상대 에이전트로 넘길지 결정한다. Claude처럼 응답을 콘텐츠 블록 리스트로 반환하는 모델을 고려해, 리스트인 경우 각 블록의 텍스트를 합쳐서 검사한다.

python종료 판단 라우터
def router(state: MessagesState):
    content = state["messages"][-1].content
    if isinstance(content, list):
        content = " ".join(b.get("text", "") for b in content if isinstance(b, dict))
    return END if "FINAL ANSWER" in content else "continue"

순환 그래프 구성

researcher와 chart_generator 두 노드 사이에 양방향 조건부 엣지를 연결해 순환 구조를 만든다. 한쪽이 작업을 끝내지 못하면 상대에게 넘어가고, FINAL ANSWER가 나오면 종료한다. 무한 루프를 막기 위해 실행 시 recursion_limit으로 최대 반복 횟수를 제한한다.

01researcher가 데이터 수집
02FINAL ANSWER 미포함 → chart_generator로 이동
03chart_generator가 시각화 코드 실행
04FINAL ANSWER 포함 → 종료
python양방향 순환 그래프
workflow = StateGraph(MessagesState)
workflow.add_node("researcher", research_node)
workflow.add_node("chart_generator", chart_node)

workflow.add_conditional_edges("researcher", router,
    {"continue": "chart_generator", END: END})
workflow.add_conditional_edges("chart_generator", router,
    {"continue": "researcher", END: END})

workflow.add_edge(START, "researcher")
app = workflow.compile(checkpointer=MemorySaver())

실행 예제로 "2010~2025년 대한민국 1인당 GDP 추이를 시각화"를 요청하면, researcher가 연도별 GDP 수치를 표로 정리해 chart_generator에게 넘기고, chart_generator가 matplotlib 코드를 실행해 그래프를 그린 뒤 FINAL ANSWER로 마무리한다.
